# Future features

## App Main page
The app main page will be a new page where the user can access the different activities that he can start once he passed the initial home page experience and configured his initial settings.
Currently the only activity is the main SRS driven reading / meaning quizzes. but the idea would be to re-organize the app structure around this 'main' page to access the different activities once there will be new one.
The mechanism of quizz session will make much more sense because we will add cards in this page to start a session of quizz (all available vocab at the start of the session). the user will be able to leave the session whenever he want to do other things, this would close the session early.
if he want to resume the quizz this will just create a new quizz session with all the currently available vocab (so there could have been new one in the meantime). this mean that going to another page during the session would obviously close the current session.
The other features like settings, stats and kanji should be available from this activity page. activities should be available in cards in the main page (they are the main actions) while other pages like stats, settings and kanjis would be in a different navigation part (like a toolbar or a sidebar).

## Grammar Activity
One of the goal would be creating a new activity to learn grammar with the same srs mechanism as the current vocab activity. the would require deciding on the best way to teach grammar points with a 'determinist' quizz response (either correct or wrong). this would also require finding a grammar rule dataset to incorporate in the app and that would fit the question system we want to create. the grammar points should be linked to a jlpt level and it would be nice to be able to leverage the vocab the user knows about to use them in this quizz. the app should feel like an ecosystem that understand what you know to help you focus on what we want to learn and avoid showing you unknown concept that will steer you from learning the object of your current activity (showing completely unknown vocab or kanji while learning grammar points add confusion).

## Static pages for kanji, vocab, grammar pages.
This would be a nice addition, making gokan a useful dictionnary for user that don't use it as an active learning tool. they could just happen to use it to search for language elements. these static page should have good seo and be crawled by the seo engine. this would require isolating the quizz linked elements of the vocabs and kanji pages so they don't show on the default static pages and only show for active users of the srs system. this also requires not automatically redirecting user to the home page when they want to search and access in language static pages.
Maybe this could be done in a separate repo to make for a clean separation between gokan-srs the learning tool and gokan-??? the dictionnary. if we do this i would advocate to create a gokan-dataset repository to hold the main dataset that is open to everyone.
The dataset compiled file should still be available from the s3 even after compiling static pages.

## Gokan-srs-api
In the future it would be nice to create a real database to store user accounts and a few things about user who registered and their progression. this would allow user to not hold the data themselves. then this would allow for creating an API, serverless would be a good way to keep the cost low. the need comes from the quizz validation mechanism with AI. currently the users need to use their own key but the goal would be to move the validation logic to a serverless lambda on AWS and make the AI processing in cloud. obviously this would be costly and should only be allowed for user that pay a subscription. other user would still be allowed to use their own key, they could even still be allowed to use a google account to store their own progress. only paid user would have real accounts.
